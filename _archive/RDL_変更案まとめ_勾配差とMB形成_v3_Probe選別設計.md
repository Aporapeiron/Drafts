# RDL 変更案まとめ
## 勾配差・変化履歴・M_B形成と未知高負荷代謝に関する再整理案

*Draft / discussion summary / updated v3*

---

## 0. この文書の位置づけ

本書は、RDL T0 基底仮設（HYP）および T0 最低動作仕様（SPEC）を前提としつつ、
以下の議論から生じた変更候補を整理するための暫定文書である。

- 同一の更新前 `M_B` で `F` と `F'` を形成することへの違和感
- 相互作用そのものが `M_B` を変化させる可能性
- `M_B` よりも変化量・勾配差を一次的に扱う可能性
- 初期には未分化な `ξ` しかなく、変化履歴から `M_B` が析出する可能性
- `M_B` を「生き残った履歴」「残存した関係構造」として再解釈する可能性
- T1 基本代謝との対応

本書は現時点では**変更確定案ではなく、再設計候補の整理**である。

### v3 追記：Probe / Selection の設計責務

本版では、未知探索に必要な `Probe` と `Selection` を基底側で一意に固定しない。

- `Probe` の具象実装は、各系の境界・身体・感覚器・センサ・API・UI・実験装置などの設計場所へ委ねる。
- `Selection` の具象基準は、境界 `B`、目的、破断条件、許容損失などに依存する設計問題として扱う。
- Probe / Selection 自体も有限構造であり、RDLの自己例外化禁止に従って再検査・再設計可能とする。


### 0.1 最新整理：基底置換案ではなく「未知用高負荷モデル」として扱う

その後の検討により、本書で扱う

```text
ξ
→ Probe / interaction under B
→ 差・勾配・変化候補
→ 候補構造群
→ Selection under B / goal
→ 残存候補
→ 再構成
→ M_B'
```

ただし、ここでの `Probe` と `Selection` は自然に一意決定される基底演算ではない。
**Probe の具象実装は各系の境界（身体・センサ・インターフェース等）の設計場所へ委ね、Selection の具象基準も対象・目的・許容損失に応じた設計問題として扱う。**

という流れは、RDLの通常時の最低動作を全面的に置き換えるものではなく、
**既存の `M_B` では吸収・解消できない不整合が閾値を越えたときに起動する、未知へ向き合うための高負荷代謝**として位置づける案が有力になった。

圧縮すると、

```text
通常時
M_B を使って解釈・予測・局所更新する

H ≥ θ
↓
再編相 M_Δ
↓
既存 M_B 自体を検査対象へ移す
↓
ξを含む未回収関係から候補構造を展開する
↓
破断・選別・残存抽出・再構成
↓
M_B'
↓
通常運転へ復帰
```

と整理できる。

この整理では、現行T0の `F / F' / E / H / θ` はまず通常運転および高負荷モードの起動判定に残し、
本書の中心課題は **`H ≥ θ` 後の `M_Δ` 内部で、どのように未知から次の `M_B` を形成するか** へ移る。

## 1. 現行T0に対する主要な違和感

現行SPECでは、概ね次の形をとる。

```text
F(t)    = interp(M_B, EFP(t))
F'(t+Δ) = interp(M_B, EFP(t+Δ))
E       = Δ(F, F')
```

ここでは比較条件を揃えるため、`F` と `F'` の双方を**同一の更新前 `M_B`**から形成する。

しかし、相互作用を考えると、

```text
EFP → M_B
```

という作用が発生した時点で、`M_B` 自体も微小に変化している可能性が高い。

したがって実際の系では、

```text
M_B(t) ≠ M_B(t+Δ)
```

であることが自然であり、

> 一回目の作用を受けても変化しない `M_B` が、二回目の作用を解釈する

という構図は、比較器としては便利でも、実際の力学としては凍結しすぎている可能性がある。

ただし、この違和感は直ちに現行SPEC全体の破棄を要求しない。
通常運転では同一 `M_B` による比較を安価な比較器として利用し、
**その比較では吸収できない不整合が蓄積して `H ≥ θ` に達した場合にのみ、自己構造の実変化を前景化する**という二段構えが可能である。

## 2. 人間の視覚系を使った検討

人間の目では、入力を受けること自体が視覚系の状態を変える。

例：

- 明所から暗所への移動
- 瞳孔径の変化
- 網膜感度の変化
- 視細胞の順応
- 残像
- 後段視覚処理の利得変化

この場合、

```text
EFP_0 → F_0
```

だけでなく、同時に

```text
EFP_0 → δM_B
```

も起きていると考える方が自然である。

したがって、次の入力 `EFP_1` は、

```text
F_1 = interp(M_1, EFP_1)
```

として形成される。

ここで

```text
M_1 = M_0 + δM
```

である。

この観点では、相互作用は「解釈を出す処理」ではなく、同時に「自己構造を変える処理」でもある。

## 3. 固定 `M_B` は実状態ではなく比較器として残す

同一 `M_B` を完全に捨てる必要はない。

むしろ、固定 `M_B` は**反実仮想的な比較器**として残すとよい。

```text
M_0 = M_B(t)
```

現在構造から予測を形成する。

```text
F_hat = Pred(M_0, EFP_t)
```

後続作用を受けた実際の自己構造は変化する。

```text
M_1 = Interact(M_0, EFP_{t+Δ})
```

実際の後続解釈：

```text
F = interp(M_1, EFP_{t+Δ})
```

比較用の凍結解釈：

```text
F* = interp(M_0, EFP_{t+Δ})
```

このとき、

```text
E_ext  = Δ(F_hat, F*)
E_self = Δ(F*, F)
E_all  = Δ(F_hat, F)
```

と分けられる可能性がある。

- `E_ext`：自己構造を固定した場合の入力側変化
- `E_self`：相互作用による自己側変化の影響
- `E_all`：実際の総不整合

この整理により、比較可能性と相互作用性を両立できる。

特に通常運転では、現行SPECの同一 `M_B` 比較をそのまま利用できる。
`M_B` の実変化を詳細に追跡する必要が生じるのは、主として閾値超過後の再編局面である。

## 4. 高負荷再編時に `M_B` より変化量を一次に置く案

議論を進めると、**再編相 `M_Δ` の内部**では、主役を状態 `M_B` そのものではなく、

```text
ΔM_B
```

へ移した方が自然である可能性がある。

これは通常時の最低動作を `ΔM_B` 中心へ全面置換するという意味ではない。
通常時は既存 `M_B` を足場として高速に処理し、既存構造そのものを作り直す必要が生じたときだけ、変化量・変化履歴を一次的に読む。

従来：

```text
M_B → F → E → H → Update(M_B)
```

変更候補：

```text
EFP → ΔM_B → M_B'
```

そして `F`、`E`、`H` は、`ΔM_B` の異なる断面・読み取りとして扱う。

例えば、

```text
δM_t = Φ(M_t, EFP_t, ξ_t)
```

を基本運動とする。

そこから、

```text
F_t = I(δM_t, M_t)
E_t = D(δM_t, δM_hat_t)
H_t = Accum(E_t)
```

を派生させる。

このとき予測も、

```text
次に世界がどうなるか
```

ではなく、

```text
次の相互作用によって自己構造がどう変わるか
```

へ寄せられる。

```text
E = Δ(δM_hat_{t+1}, δM_{t+1})
```

この方が、RDLが世界そのものではなく有限境界内の作用・解釈を扱うという前提と整合しやすい。

## 5. 未知探索の開始状態：まず `ξ` としてしか扱えない

高負荷再編を「未知へ向き合う処理」として見る場合、探索開始時点では、対象について有効な `M_B` がまだ成立していない、または既存 `M_B` が失効している可能性がある。

したがってここでいう「初期」は、宇宙論的・絶対的な始原を意味せず、**現在の境界 `B` において構造化に失敗している局面の開始状態**を意味する。

その局面では、

```text
ξ
```

としてしか扱えない未分化・未回収の関係がある。

そこから変化が起きる。

```text
ξ → Δ_1 → Δ_2 → Δ_3 → ...
```

最初は「何があるか」は分からない。

しかし、変化列の中に、

- 反復する差
- 消えにくい差
- 戻りやすい差
- 特定方向へ偏る差
- 他の変化を拘束する差

が現れると、そこから持続的構造を抽出できる。

```text
ξ
→ Δ
→ pattern(Δ)
→ M_B
```

したがって、`M_B` は最初から存在する既知構造ではなく、

> 未知の変化履歴から析出した一時的な整合構造

として理解できる。

---

## 6. 「分からないもの」だけから「分かるもの」が生まれる

ここで重要なのは、

```text
ξ = 無秩序
```

ではないことである。

`ξ` はあくまで、

```text
ξ = 現在の境界では分からない / 回収されていない関係
```

である。

したがって、最初は全てが未分化でも、変化履歴を追うことで、

```text
同じように変わる
繰り返す
戻る
残る
偏る
```

という関係は抽出できる。

「分かる」とは、未知そのものの正体を完全に知ることではなく、

> 未知の変化の中に、再現・予測可能な関係が析出すること

と捉えられる。

このとき、

```text
ξ → M_B + ξ'
```

となる。

未知が既知へ完全変換されるのではなく、未知の中から一時的な既知構造が立ち上がる。

## 7. ランダムウォークとの対応

初期状態を簡略化すると、ランダムウォークに近い形で考えられる。

```text
x_{t+1} = x_t + η_t
```

ここでは、まず変化しか観測できない。

```text
Δx_t = η_t
```

完全にランダムであれば、持続的構造は抽出できない。

しかし実際の変化列に、ランダムでは説明しきれない偏りが継続するなら、

```text
persistent deviation from random walk
```

を構造候補として拾うことができる。

したがって、

```text
M_B = ランダムでは説明しきれない変化の持続的偏り
```

という理解が可能である。

ただし、

```text
ξ ≠ random
```

である。

ランダムは `ξ` の定義ではなく、構造未抽出時の零仮説に近い。

---

## 8. 生存バイアス的ランダムウォーク履歴

さらに、変化の全履歴が残るわけではない。

```text
{Δ}_{all}
```

のうち、

- すぐ消えるもの
- 打ち消されるもの
- 破断するもの
- 他の変化に吸収されるもの

は残存しない。

一方、

- 何度も再現される
- 他の変化を拘束する
- 破断しにくい
- 同一条件下で残存しやすい

関係は履歴として厚くなる。

```text
{Δ}_{all}
→ Selection_{B,goal}
→ {Δ}_{retained}
```

ここで何を「残った」とみなすかは、境界 `B`、探索目的、破断条件、許容誤差などに依存する。
したがって残存は無条件の自然淘汰ではなく、**有限な Selection 設計を通過した残存候補**として扱う。

その圧縮が `M_B` になる。

```text
M_B = retained history under finite Selection
```

あるいは、

> `M_B` は、過去の相互作用の中で消滅せず残った関係履歴の束である。

と表現できる。

## 9. 自由度の高い `M_B` が消滅し、安定構造が残る

初期には、多数の構造候補が立ち上がると考えられる。

```text
M_B^(1), M_B^(2), M_B^(3), ...
```

相互作用を受けるたびに、維持できない候補は消滅する。

```text
M_B^(i)
→ interaction
→ ∅
```

一方、自己維持できる候補は残る。

```text
M_B^(j)
→ interaction
→ M_B^(j)'
```

その結果、構造群は概ね、

```text
高自由度・破断しやすい候補
→ Selection_{B,goal}
→ 現在条件でより残存しやすい構造
```

へ移る。

ただし、これは単純な自由度減少ではない。

より正確には、

> 破断しやすい自由度が削られ、相互拘束された自由度が残る

と考える方がよい。

したがって安定とは、

```text
stability = 特定B・特定条件・特定Selection下での残存性
```

であり、絶対的・終端的安定ではない。
Selection の設計を変えれば残存構造も変わりうるため、選別結果をそのまま世界側の絶対的性質へ昇格させない。

## 10. 空気と風：構造化の例

空気は常に存在していても、通常は強く意識されない。

しかし、圧力差・温度差・速度差などが生じると流れが発生し、「風」として構造化される。

重要なのは、空気そのものではなく、

```text
勾配差
```

である。

例えば、

```text
∇P ≠ 0
∇T ≠ 0
```

によって流れが生じる。

人間は「風」を直接単一入力として受けるのではなく、

```text
Δ皮膚
Δ髪
Δ葉
Δ音
```

など複数の変化の相関から、風という構造を切り出す。

```text
{Δ_skin, Δ_hair, Δ_leaf, Δ_sound}
→ correlated gradient pattern
→ M_B(風)
```

この例から、高負荷探索において構造候補を拾う有力な観測量として、単なる変化量より、

```text
勾配差
```

が有効である可能性が高い。

ただし、これは `ξ` 自体の内部に「勾配差」が基底実体として存在すると宣言するものではない。
有限境界 `B` のもとで未知へ探索操作をかけた結果、観測可能な差・変化列の偏りとして勾配候補が得られる、と読む方が安全である。

## 11. 勾配差を一次量とする案

候補となる基本流れ：

```text
ξ
→ 勾配差
→ 流れ
→ 持続する流れ
→ 構造化
→ M_B
```

より圧縮すると、

```text
ξ
→ ∇
→ flow
→ persistence
→ M_B
```

状態そのものより、状態間の差、さらにその空間的・時間的勾配差が構造を立ち上げる。

したがって、勾配差はRDL全体の新しい基底Primitiveへ直ちに昇格させるより、
**未知探索時に構造候補を生成するためのT1操作量**として扱う方が現時点では自然である。

```text
ξ
↓ Probe / interaction under B
観測可能な差・変化列
↓
勾配候補 ∇
↓
構造候補
```

この形なら、HYPの `ξ = 未回収関係` を変更せずに、勾配差の有効性だけを取り込める。

### 11.1 `Probe` は設計問題である

ここでの `Probe` は、未知そのものを直接読む万能観測ではない。
RDL Core 側では、せいぜい次の抽象関係までを置く。

```text
Probe_B : unresolved interaction
          → B 内で比較可能な差・変化候補
```

しかし、実際に

```text
何を受け取れるか
何を刺激できるか
どの分解能で測るか
どの時間幅を取るか
どのチャネルを開くか
Probe 自体が対象へどの程度作用するか
```

は系ごとに異なる。

したがって、

> **Probe の具象実装は、各系の境界――身体・感覚器・センサ・API・UI・実験装置など――を設計する場所へ委ねる。**

とする。

圧縮すると、

```text
B     = 何を扱える範囲とするか
Probe = その範囲へどう結合するか
```

である。

RDL側で重要なのは Probe の具体方式ではなく、少なくとも

```text
Probe は有限境界 B に依存する
Probe の取得結果を世界そのものと同一視しない
Probe によって回収できない関係を ξ として残す
Probe 自体の相互作用・偏りも再検査可能である
```

ことを保持する点にある。

### 11.2 `Selection` も設計問題である

同様に、候補構造の選別も自然に一意決定される処理ではない。

```text
Selection_{B,goal}(candidate)
→ retain / reject / defer
```

と抽象化できるが、具象的には

```text
何を破断とみなすか
何回の再現を要求するか
どの条件を変えるか
何をコストとするか
偽陽性・偽陰性をどう配分するか
何を「残存」と呼ぶか
```

を設計しなければならない。

したがってT1では **「検査と選別が必要である」こと**を保持し、
その選別関数の具体形は、T2または各対象系の設計層へ委ねる。

さらに、Probe と Selection 自体も有限構造である。

```text
Probe_design ∈ finite structure
Selection_design ∈ finite structure
```

ゆえに、それらを例外化せず、必要なら

```text
Probe / Selection
→ SILN_SELF
→ 条件変更・耐久検査
→ 再設計
```

できなければならない。

この点により、高負荷代謝は「未知から真の構造が自動析出する機械」ではなく、

> **有限な観測設計と選別設計を用いて未知へ接続し、その設計自体も再検査しながら、現在使える構造を形成する探索設計過程**

として位置づけられる。

## 12. T1基本代謝との対応：通常代謝と高負荷代謝

ここまでの議論は、T1基本代謝そのものを全面的に置き換えるというより、
**T1が閾値超過時に深く回る高負荷分岐**として整理するのが自然である。

既存のT1基本形：

```text
SILN展開
↓
検査と選別
↓
再構成
```

通常時には、既存 `M_B` を足場として比較的低コストに処理する。

```text
EFP
↓
M_B による解釈・予測
↓
F / F'
↓
E
↓
H
↓
H < θ
↓
維持・局所更新
```

一方、既存構造で吸収できない不整合が残り、

```text
H ≥ θ
```

となった場合、再編相 `M_Δ` に入り、高負荷代謝を起動する。

```text
H ≥ θ
↓
M_Δ
↓
既存 M_B を検査対象化
↓
ξを含む未回収関係へ探索を拡張
↓
Probe_B を通じた差・変化・勾配候補の展開
↓
候補構造群 {M_B^i}
↓
Selection_{B,goal}
↓
破断・棄却・保留・残存
↓
残存関係の抽出
↓
再構成
↓
M_B'
```

T1基本工程との対応：

| T1工程 | 高負荷再編時の解釈 |
|---|---|
| SILN展開 | 設計された `Probe_B` を通じて得た差・変化から、既存 `M_B` 自体を含む複数の候補構造を展開する |
| 検査と選別 | 設計された `Selection_{B,goal}` のもとで条件変更・相互作用・破断を行い、候補を残す・落とす・保留する |
| 再構成 | Selection を通過して残った関係履歴を圧縮し、次の `M_B'` として形成する |

したがって、

> `M_B` を「使う」処理は通常代謝、`M_B` そのものを「作り直す」処理は閾値超過後の高負荷代謝として分ける。

という整理が有力である。

## 13. T0 / T1 / T2 の責務分担候補

### T0

T0は現行の基底条件と最低動作を極力保持する。

```text
B
ξ
M_B
EFP
F / F'
E
H
θ
維持・局所更新 / 再編
```

T0の責務は、

```text
既存 M_B で処理できる間は通常運転する
H が蓄積し θ を越えた場合は再編へ移行できる
更新後も ξ を伴う
```

ことを保証するところまでとする。

T0で `ξ → 勾配差 → M_B` の具体的生成アルゴリズムをPrimitiveとして固定しない。

### T1

T1では、通常の代謝に加えて、`H ≥ θ` 後の `M_Δ` 内部で

```text
未知へ探索を拡張
→ Probe_B を通じた差・変化取得
→ 候補展開
→ 検査
→ Selection_{B,goal}
→ 残存抽出
→ 再構成
→ M_B'
```

という高負荷代謝を扱う。

### T2

T2では、高負荷代謝を実際にどう動かすかを具体化する。

例：

```text
勾配探索
反復検出
候補生成
条件変更
破断検査
残存抽出
比較
圧縮
```

ただし `Probe` の具象実装はT2へ一律固定しない。
身体・感覚器・センサ・API・UI・実験装置など、**対象系の境界／インターフェースを設計する場所**に実装責務を置く。
Selection の具体基準も同様に、目的・対象・許容損失を定める設計場所へ委ねる。
T2は必要に応じ、それらの設計・耐久検査・比較を支援する機構を提供する。

したがって役割を圧縮すると、

```text
T0 = いつ通常運転を続け、いつ再編へ入るかを定める
T1 = Probe・検査・Selection・再構成という高負荷代謝の抽象工程を保持する
T2 = その工程を動かす汎用機構・耐久検査・比較手段を提供する
各系設計 = Probe の身体／インターフェースと Selection の具体基準を実装する
```

となる。

## 14. 現行 `F / F' / E / H / θ` の扱い

今回の整理では、現行SPECの `F / F' / E / H / θ` を直ちに再定義する必要は薄くなった。

むしろ、これらは**通常運転と高負荷モードの起動判定を成立させるために残す**。

### 14.1 `F'`

現行：

```text
F' = interp(同一の更新前M_B, 後続EFP)
```

これは通常時の比較器として維持可能である。

同一 `M_B` で比較することにより、現在構造の予測がどれだけ外れたかを安価に検出できる。

一方、再編相では実際の自己変化を追う必要があるため、補助的に

```text
F* = interp(M_0, EFP_{t+Δ})
F_real = interp(M_1, EFP_{t+Δ})
```

のような固定比較と実状態を分けるモデルを導入してもよい。

### 14.2 `E`

現行：

```text
E = Δ(F, F')
```

も、通常運転では維持する。

高負荷再編内部では必要に応じて、

```text
E_ext
E_self
E_all
```

あるいは

```text
予測された ΔM と実際の ΔM の差
```

を補助誤差として導入できる。

ただし現時点では、T0の `E` をこれに置換するところまでは確定しない。

### 14.3 `H`

`H` は引き続き、既存構造で吸収・解消されず残存した不整合の蓄積として扱う。

そのうえで、今回の整理では `H` にもう一つ重要な役割が加わる。

> `H` は、通常処理を続けるか、既存 `M_B` 自体へ向き合う高負荷再編へ移るかを判定するための蓄積状態である。

### 14.4 `θ`

`θ` は単なる「壊れる点」ではなく、

```text
既存 M_B を使う側
        ↓ θ
既存 M_B 自体を検査対象にする側
```

への切替境界として解釈できる。

### 14.5 更新

更新は二段に分ける。

```text
H < θ
→ 維持・局所更新

H ≥ θ
→ M_Δ
→ 高負荷探索・再編
→ M_B'
```

常時微小更新 `δM_B` を認めるとしても、それと大規模な構造再編は同一視しない。

## 15. `M_Δ` の再解釈：未知へ向き合う高負荷状態

今回の整理で最も重要なのは、これまで遷移記号として置かれていた `M_Δ` の内部に意味を与えられることである。

候補定義：

> `M_Δ` とは、既存 `M_B` だけでは不整合を吸収できなくなり、既存構造自体を検査対象へ移し、未回収関係 `ξ` を含む探索空間から次の整合構造を形成している再編状態である。

圧縮すると、

```text
M_B
↓ interaction
E / H ↑
↓
H ≥ θ
↓
M_Δ
= High-load Unknown Mode
↓
{既存M_Bの分解, ξ探索, 候補展開, 破断, 選別, 残存抽出}
↓
M_B'
```

この意味で、「未知へ向き合う」とは単に情報量が増えることではない。

通常時には、

```text
M_B → 対象を読む
```

のに対し、再編時には、

```text
M_B → 検査対象化
```

が起きる。

すなわち、**自分が対象を見るために使っていた構造そのものを、いったん対象側へ回す**。

これはRDLの自己適用・再構成原則とも整合する。

> 小さなずれは、その構造の中で直す。

> その残存関係から次の `M_B` を作り、再び通常運転へ戻る。

## 17. 暫定定義候補

### `ξ`

現在の有限境界では回収・構造化されていない関係。

```text
ξ ≠ random
ξ = uncollected / unresolved relation
```

### 勾配差

`ξ` の基底属性として直接仮定するのではなく、有限境界 `B` のもとで未知へ探索・相互作用をかけたとき、観測可能な差・変化列の中から検出される局所的・時間的偏り。

```text
Probe(ξ, B)
→ {Δ}
→ gradient candidate ∇R
```

現段階ではT0 Primitiveではなく、T1高負荷代謝の操作量候補とする。

### `Probe_B`

未知・未回収関係へ接続し、現在の有限境界 `B` 内で比較可能な差・変化候補を取得するための抽象操作。

```text
Probe_B : unresolved interaction → observable differences under B
```

具象実装はCoreでは固定せず、各系の身体・感覚器・センサ・API・UI・実験装置など、境界／インターフェースの設計場所へ委ねる。

### `Selection_{B,goal}`

候補構造に対し、現在の境界・目的・破断条件・許容損失のもとで、残す・落とす・保留するための有限な選別設計。

```text
Selection_{B,goal}(candidate)
→ retain / reject / defer
```

Selection の結果は絶対的真理ではなく、その設計条件下での暫定的残存判定である。
また Selection 自体も再対象化・再検査・再設計の対象になる。

### `ΔM_B`

相互作用によって有限構造に生じる変化量。

通常時にも微小に生じうるが、高負荷再編時には構造形成・選別を読む主要量候補になる。

### `M_B`

候補定義：

> 有限境界 `B` のもとで、相互作用と有限な `Selection_{B,goal}` を通過し、現在まで残存候補として保持されている関係履歴の圧縮構造。

別表現：

> `M_B` は、過去の勾配差と変化のうち、破断・消滅せず残った関係が作る一時的な整合慣性である。

### `M_Δ`

候補定義：

> 既存 `M_B` では吸収できない不整合が閾値を越えたとき、既存構造自体を検査対象化し、未知から次の整合構造を探索・選別・再構成している高負荷再編状態。

## 18. 未決事項

今回の整理によって、いくつかの論点は暫定的に後退または整理された。

### 現時点でやや整理された事項

1. `ξ → 勾配差` をT0の直接生成則として置く必要は薄い。
2. 勾配差は当面T0 Primitiveではなく、T1高負荷代謝の探索・観測量候補とする。
3. 現行 `F / F' / E / H / θ` は直ちに全面改訂せず、通常運転と高負荷起動判定に残す。
4. 常時微小更新と、`H ≥ θ` 後の大規模再編は別レベルとして扱う方向が有力である。
5. `M_B` の生成・再生成過程は、T1高負荷代謝として扱う方向が有力である。
6. `Probe` の具象実装はCoreで固定せず、各系の境界・身体・インターフェース設計へ委ねる。

## 19. 現段階の要点

現時点で最も強い整理候補は、次の八点である。

```text
1. 現行T0の通常動作は原則として残す。
   既存 M_B を使い、F / F' → E → H → θ で処理する。

2. H < θ では、維持・局所更新を続ける。
   毎回未知から構造を作り直さない。

3. H ≥ θ で、再編相 M_Δ へ入る。
   θ は「既存 M_B を使う側」から
   「既存 M_B 自体へ向き合う側」への切替境界でもある。

4. M_Δ 内部では、設計された Probe_B を通じて未知へ接続し、
   差・変化・勾配・反復などから複数の候補構造を展開する。

5. 候補の Selection は自動的に決まらない。
   B・目的・破断条件・許容損失に応じて設計し、
   retain / reject / defer を行う。

6. Probe の具象実装は、各系の身体・センサ・API・UIなど、
   境界／インターフェースを設計する場所へ委ねる。

7. Probe / Selection 自体も有限構造であり、
   必要なら再対象化・耐久検査・再設計する。

8. 勾配差はT0の新Primitiveとして直ちに固定せず、
   T1高負荷代謝で未知から構造を拾うための有力な操作量として扱う。
```

この整理を採用すると、今回の変更案は

```text
RDL全体の基底を書き換える案
```

ではなく、

```text
既存構造では処理できない未知に対し、
有限な Probe と Selection を設計し、
その設計自体も検査しながら、
RDLがどのように「向き合い」、次の構造を作るかを記述する案
```

として位置づけられる。

最短化すると、

```text
既知を扱う RDL = M_B を使う
未知を扱う RDL = M_B を作り直す
```

となる。

そして両者をつなぐ境界が、現時点では

```text
H ≥ θ
```

であり、その内部状態候補が

```text
M_Δ
```

である。
